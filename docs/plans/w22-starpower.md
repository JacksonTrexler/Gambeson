Goal (user, follow-up.md F1): "Wizard, astral mage t3: Starpower: Mana is Power: now called Starpower. It regenerates like Power and can be used like Power **only for power exclusive skills**: cannot be used as energy. +Rank Starpower. `Starpower` is greenish teal" / "Wizard, mage: Mana Resonance: Unit energy is now mana. Abilities that use energy consume AP instead. Exhaustion penalty, base + base*(1/rank). *icon is blue star with yellow circle behind*". Names user-given (--human): Starpower, Mana Resonance.

## Readings and calls
- Where "astral mage" is: `Trees/astral.tres` is the Druid's. The Mage's astral school is `Trees/stars.tres` (Stars: Fortune, Constellation, Starfall; Wizard borrows School via Mastery). Starpower goes there, after Starfall = depth 3 (t3). Sibling w22-astral1 may touch Trees/stars.tres: a one-branch diff.
- One generic rule: Effect `acts_as`, tags [pool id, Reserves/ file id]: "this unit's pool follows that reserve's rules, name, colour" (`Unit.view(pool)`; pool = &"energy" or a Reserve). Identity (store key, items, cost_with, role.reserves) stays the original reserve; anything reading what a reserve IS (what it pays, regen, name, colour, replaces) asks `view()`. Starpower = `acts_as [mana, starpower]`, Mana Resonance = `acts_as [energy, mana]`.
- "Power" for a reserve = `Reserve.powered` (new field; Reserves/starpower.tres: name Starpower, teal (0.15, 0.72, 0.6), only [power], no with_energy, not replaces). Energy's Power stays the `powered` stat.
- "Regenerates like Power": Power never comes back on its own (Effect powered) but does on the star lattice x2..x5 (Battle._starlight). So Starpower: no own regen (view has no with_energy), comes back by the lattice's whole boost (`Unit.grant_power()` from `_starlight`), and by anything that restores that reserve. Not by Energy grants (a unit with both pools would be doubled).
- "Power exclusive skills": new tag `power` (--human, Glossary "Power"). A skill tagged power is paid only by Power: a `powered()` unit's Energy, or a reserve whose view is `powered`. Plain Mana and plain Energy never pay it. NO existing skill carries it (tagging Starfall would lock out non-powered Mages): the sibling's startile-family skills (and later Power skills) should carry `power`; until then Starpower has nothing to pay. Open for the user.
- "Cannot be used as energy": the view has `replaces` false, so `runs_on()` skips Mana's toggle: a Starpower Wizard runs on Energy again (Energy refilled at max by `energy = ...` next battle start) and its Mana pays no ordinary spell. A real economy hit: it is the cost of the skill (the user's wording).
- "+Rank Starpower": new Effect `pool_max` (tags [pool id], x rank): +1 max per rank on the Mana pool (`pools()`). Generic (items could use it).
- Mana Resonance "Unit energy is now mana": `runs_on()` returns the Mana reserve (Energy acts as it), i.e. the Wizard/Mage's existing Mana-for-Energy stand-in, forced (the toggle is moot) and given to any unit holding a Mana pool. One pool named Mana. If the unit's Mana is also Starpower, Energy is Starpower.
- "Abilities that use energy consume AP instead": Effect `cost_ap` (tags [pool], AP per point): a cost paid from that pool is 0 and `ap_cost()` adds `cost x rate` AP (then exhaustion's multiplier). Call: 0.5 AP per Energy point (knob = the effect's amount). Applies to what funding() picks as Energy: only for skills no Mana-style reserve is dedicated to (`only` set): a spell with the Mana short is NOT paid in AP (no free spells with an empty Mana); non-magical skills (and any non-power skill when Mana is Starpower) cost AP only.
- "Exhaustion penalty, base + base*(1/rank)": Effect `wear`, amount 1: exhaustion's wear on its skills = base x (1 + amount / rank) (`Unit.wear_penalty()`, multiplied into Exhaustion.penalty after Burnout's). Rank I x2, II x1.5, III x1.33.
- Resonance placement: Mage's Commitment root (skill.py) and Wizard's Arcane root (hand-added branch: no tool for a second tree), no prerequisite, max_rank 5. The user said "Wizard, mage": read as both classes.
- Icons (Util/icon.py `star`, new): Starpower a teal star; Mana Resonance a blue star on a yellow disc ("blue star with yellow circle behind": disc behind, star in front). Coloured, not white-on-clear, so the skills screen's tint reads weakly.
- HUD rows and unit bars read `view(r)` name/colour ("ST", teal). A Starpower row label collides with Stamina's "ST" if a unit has both (undone).
- Names carrying ??: Effect stat titles "Acts as ??", "Max ??", "Paid in AP ??", "Wear ??". Stats acts_as, pool_max, cost_ap, wear; Reserve.powered; tag power (--human).
