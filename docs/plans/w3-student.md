# w3-student: the Student tree, composed into the Mage's general tree

User (answers-2026-11-18b item 5): "Mage general skills reflecting study practice should be loaned from specialist student skill tree, which is also available to any class selecting specialist flex trees"; "refactor in a manner where skills added to student skill tree show up in the mage general tree: the mage general tree is composed of its unique skills *and* skills in the student skill tree".

## Readings and calls

1. **"Mage general tree" = the Caster general tree (Trees/general_caster.tres, category magical).** It is the one place tiers are set (T7 is Cram's place) and it is every magical class's general tree, the Mage's included. A class-own-tab reading was rejected: its tiers are counted from prerequisites (Role.tier), so Cram could not sit at T7. Consequence: every caster (Wizard, Cleric...) sees Student's skills on its Caster tree, not only the Mage. Ask the user if Mage-only is wanted (it would be a per-role include, a bigger change).
2. **Composition is one field: `SkillRoot.includes: Array[SkillRoot]`.** A root's `skills()`, `branch()`, `depth()` and `all_branches()` read through it (own branch first, each skill once, loop-safe), so every reader (SkillTab.tier_of/offers, SkillGrid, SkillWheel, Unit.general_skills, Unit._general_need, HUD) gets included skills with no change of its own. Not copies: a skill added to Student shows everywhere it is included with its Branch tier and prerequisites.
3. **Student is a root file, `Trees/student.tres`** (name "Student", tag specialist; the user's names, `--human`, no ??). The Specialist general tab includes it too ("any class selecting specialist flex trees"), and so does Caster. No new TreeChoice for "specialist flex trees": no class has such a choice yet.
4. **Student is seeded with Discipline (T3), moved off the Specialist root.** The tools refuse an empty tree (role.py check), and Discipline is the existing "study practice" skill (already in the Mage's options). Its tier (3) and its place on the Specialist tab are unchanged; it now also shows on the Caster tab. Cram (w3-cram) goes on with `python3 Util/skill.py new cram --tree student --branch-tier 7`: no further wiring.
5. **An included skill keeps its own tree's kind and category**: `Skill.kinds()` (Exhaustion, typed slots) reads `own_skills()`, and `Role.category` reads `SkillRoot.source(s).tag`. Discipline stays specialist, not magical, on the Caster tab. Chosen so composition never changes what a skill is; a shared tag on the skill is the way to widen that.
6. **Tools.** `Util/tres.py composition_problems()`, run by `skill.py check` and `role.py check`: includes loops, a skill twice in the composed whole, an include that is not a tree root, a prerequisite not held by the composed tree, a prerequisite tier not below its dependant's, an untiered branch in a tiered tree. New `role.py include <into> <tree> [--root]` writes the `includes` line and rolls back if the checks then find something new. `skill.py new --tree student` already places a skill on Student, which is all Mage general needs.
7. `.claude/skills/new-skill` and `new-class` were not edited (off limits); they should mention `role.py include` and Student.
