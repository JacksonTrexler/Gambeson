# AI support and weighing (z-aisupport, 2026-11-15)

Branch `z-aisupport`. Card "AI support and weighing" in `docs/queue.md` minus its last item (a switch where no pool holds enough: ?130, left open). Baseline 8416 checks (888 tests); after, merged with `adventurer-skills` (equipping): 8644 checks, 0 failed (894 tests).

## Calls (each open for review)

1. **Move ??'s extra effect.** New generic hook `Behaviour.strides(c) -> int` (tiles of movement the cast gives its caster this turn, as it would be paid *now*; added to `Util/skill.py` HOOKS). `Move.strides` reads `pays_as(skill, funding(skill), STAMINA)`, so Stamina doubles it in the forecast as in `apply()`. Before it walks on a foe (the `_rally` branch of `act()`), `AI._stretch()` finds the tiles each affordable foe skill still needs (straight-line distance less `skill_range`, as `starve_worth` uses straight lines); if none can be walked as it stands, it casts the cheapest-AP self_only skill whose `strides()` closes the gap, with AP left to walk it and pay for the blow (`ap_left - cost + tiles - gap >= blow AP`). *Calls:* Move is chosen only to bring a blow in reach this turn (not for hunting, fleeing, or reaching a heal); straight-line gap, not the real walk; AP priced, not Energy/Stamina points; no per-skill branch, any behaviour declaring `strides` joins.
2. **Exhaustion.** `AI._wear(u, s)` = `(1 - 1/rate) x (AP cost x AP + cost points x POINT)`, the part of what s costs that exhaustion added, in the HP score() already counts. `_strike` takes it off a blow's worth, never below `1 - WORN` (**WORN = 0.8**, as FOILED), so a lone worn skill is still used. Strikes only: heals and supports are not weighed. *Result* (30 museum seeds, scratch sim, not kept): before Lancin 27 / Nemes 3, 420 turns; after Lancin 26 / Nemes 4, 413 turns; Icor Hex 126 -> 125, Strike 95 -> 92. The weighing works but Hex outscores Strike by enough that Nemes still leans on it: ?87's museum balance is not fixed by the AI alone; I did not tune WORN to hit a quota.
3. **Help orders.** `Skill.serves(posture, u = null)`: given the unit, "supportive" also holds for a skill whose behaviour `restores()` something (new `Skill.restoring(u)`; asked with a Cast of `u` on itself at rank 1: not `u.rank()`, which reads Affinity and recurses). Without a unit it can't ask and answers as before. `Unit.affinity`, `intent_skill`, `_skippable` pass `self`. `HUD.intent_skill` and `AI.restoring` are gone: the HUD asks `u.intent_skill()`. `Skill.heals()` untouched, so `Battle.cast()` heals once. *Calls:* a self-only restorer (Energize) counts as supportive despite `self_only` (the HUD's HELP already ran it); so it now serves both HELP and DEFEND, and a Berserker's Affinity for it nets -2. *Effect:* Heal and Resuscitate now get a Berserker's Unsupportive -1 like Second Wind.
